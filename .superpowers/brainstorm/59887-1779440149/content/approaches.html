三种重构路线

以 SEO impact（影响）和 effort（工作量）为坐标

方案 A：渐进增强

Impact: 中 | Effort: 低

最小改动，只加 JSON-LD、breadcrumbs 和修复 layout 语义标签。不改组件结构，不改路由。

  • ✅ 一周内可上线
  • ✅ 零回归风险
  • ❌ 播放页内容仍是客户端渲染
  • ❌ 内链矩阵和导航缺失

方案 B：结构性重构 ⭐

Impact: 高 | Effort: 中

重构 Layout 骨架，将播放页核心内容提到 Server Component 中，补充 JSON-LD + breadcrumbs + 导航，完善 sitemap。

  • ✅ 搜索引擎可抓取完整页面内容
  • ✅ Rich Results 全面覆盖
  • ✅ 内链矩阵优化
  • ⏳ 需少量组件拆分

方案 C：全量重写

Impact: 高 | Effort: 高

除了 B 的内容，还追加海报优化（next/image）、search 专用页面、about/privacy 页面、/genre/year 组合路由、sitemap index 分页。

  • ✅ 最完整的 SEO 覆盖
  • ✅ Core Web Vitals 优化
  • ❌ 改动点多，回归风险高
  • ❌ 部分改动可能不是必需的

推荐：方案 B

结构性重构在投入产出比上最优。它解决了最关键的 SEO 问题——搜索索引能抓取「可索引的内容」——同时不引入过多改动点。方案 C 中的 sitemap 分页和海报优化可以作为后续迭代。
